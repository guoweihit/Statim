# Statim 设计与实现

[English](model.md) · [项目说明](../README.zh-CN.md) · [实验指南](experiments.zh-CN.md)

Statim 让转发节点立即在本地应用路由决策，同时由控制器异步安装对应路由。
本仓库在 ns-3/ndnSIM 中实现这一设计，并以 KITE 支持的生产者移动为应用场景。
实验配置决定转发行为、流量、控制时延和观测窗口。

## 转发路径

一个 Statim 转发节点由匹配动作流水线和有状态软件模块组成。
流水线将到达的报文交给模块实施 NDN 处理。
对于 Interest，模块登记待处理状态并查询内容存储。
命中内容存储时立即返回 Data。
一个被接受且未命中缓存的 Interest 在经过配置的处理时延后进入路由查询。

模块用临时 FIB 保存本地接受的路由决策。
启用临时转发时，匹配到的临时条目提供输出端口。
其他 Interest 回到流水线，查询其中由控制器安装的流表 FIB。
输出端口位图将模块的决策带回流水线。
普通 Interest 转发从输出集合中排除入端口。

收到的 Data 经过配置的处理时延，满足匹配的待处理记录，并通过去重后的入端口集合返回。
KITE Trace Data 还会触发路由更新：其跟踪前缀确定目的地，匹配的 PIT 记录给出通往生产者的下一跳。
端点应用生成 KITE 信令，并测量生产者按计划切换接入点后接收到的请求。

## 路由更新与控制器完成

本地路由控制器按前缀接受递增的更新代次。
接受更新后，它替换该前缀原有的临时下一跳，并提交控制请求。
保存的 Trace Interest 提供路由寿命 L；在仿真时刻 t 接纳更新后，临时表项与控制消息都记录截止时刻 t+L。
流表控制器经过配置的时延尝试安装，在截止时刻之前接纳更新。
被接纳的安装使用原截止时刻，并产生完成通知 `SyncAck`。
与当前待处理代次和截止时刻匹配的通知会在路由仍有效时删除临时条目。
两张表均在截止时刻将路由视为过期。

主要移动实验采用这一正常更新路径。
附加选项支持持久代次检查、超时重试，以及在请求、安装和完成通知三个环节分别设置丢失和时延。
启用代次检查后，控制器保留各前缀已接受和已安装的最高代次，拒绝过期更新和同代次的冲突载荷，并对已经完成的相同重试返回确认。
重试预算耗尽后，本地控制器撤回临时条目及其待处理请求。
每次重试携带原截止时刻，临时状态撤回后已安装的流表路由也保留同一截止时刻。
Statim 的切换场景提供这些策略设置，独立控制程序检查丢失及事件次序案例。
路径场景采用固定控制策略，其有效参数记录在运行清单中。
[实验指南](experiments.zh-CN.md)列出各项设置的适用范围及可用功能检查。

Interest 再转发是一个独立选项。
接受路由更新后，Statim 按名称顺序枚举更新前缀下保存的 Interest，刷新 nonce，并将直接向新下一跳发送的事件安排在当前仿真时刻，数量受每次更新的上限约束。
候选范围由已存储的待处理记录决定，包括自上次聚合后入端口寿命已经到期的记录。
KITE-NFD 对照选择仍有有效入端口记录、且新接口同时未出现在入端口和输出记录中的匹配 PIT 条目。
它发送保存的 Interest，保留其原始 nonce 和报文寿命，并按 1 毫秒间隔调度相继候选的发送。
这些设置分别运行两套协议栈所实现的再转发行为。
消费者重传则单独控制消费者是否再次发送尚未满足的序列。

## 状态与查找语义

临时表和待处理表使用以完整 NDN 名称为键的 `std::map`。
本地控制器负责更新次序和单下一跳替换策略；临时表提供存储及最长前缀查找。

| 对象 | 已实现行为 |
| --- | --- |
| 待处理 Interest 表 | 保存每个名称首次接受的 Interest，并为入端口分别记录插入时间和寿命。去重比较新到达 nonce 与首次保存的 nonce。接受聚合时清理过期入端口记录。Data 满足处理消费已存储的祖先名称匹配，包含精确名称和根，并返回对应端口。前缀枚举按名称顺序给出保存的 Interest。 |
| 临时 FIB | 按前缀保存端口和截止时间。插入时清理该前缀的过期下一跳，并添加尚未存在的端口；现有有效端口保留其截止时间。查询清理过期下一跳，并可回退到较短的有效前缀。 `size()` 统计当前存储的前缀，清理发生在插入和查询时。 |
| 流表 FIB | 按优先级匹配编码后的名称字段，表示的前缀分量越多，优先级越高。控制器安装或替换路由及其超时值。 |
| 内容存储 | 使用精确名称查找和条目数量上限。淘汰先执行随机选择扫描，再按容器顺序移除条目直至满足上限。容量为零时关闭缓存。 |

Data 满足处理和待处理 Interest 枚举使用调用时已存储的记录；接受 Interest 聚合时执行待处理记录的寿命清理。
这些已存储记录可以包含自上次接受聚合后寿命已经到期的入端口记录。
状态容器使用 ndnSIM 提供的 ndn-cxx 单调时钟，独立测试注入可控时钟。

临时表匹配优先于流表匹配。
例如，对 `/alpha/item/segment`，临时路由 `/alpha` 优先于流表路由 `/alpha/item`。
查找测试包含这一跨两表合并最长前缀匹配的反例，以及五个选择结果一致的案例。
这种优先级为受影响前缀提供临时覆盖行为。

## 报文表示

NDN TLV 数据块之前带有 12 字节仿真头部：

| 字段 | 宽度 | 用途 |
| --- | ---: | --- |
| 报文类型 | 1 字节 | 处理阶段与报文类别 |
| 输出端口 | 4 字节 | 表示端口 1 至 32，端口 1 使用最高位 |
| 输入端口 | 2 字节 | 有状态模块的入端口 |
| 名称哈希 | 4 字节 | 前四个名称分量各使用一个 8 位哈希 |
| 交换机编号 | 1 字节 | 交换机元数据及 Data 跳数传递 |

每个分量的 URI 使用 `std::hash<std::string>` 后模 254，`0xff` 表示通配。
具有相同哈希元组的名称共享流匹配表示。
因此，实验中的所有仿真节点使用同一套已记录的编译器和库环境。
状态容器接受 16 位端口号，报文输出动作使用 32 端口位图。
匹配字段采用比特偏移，字段写入动作采用字节偏移。

## 仿真假设

移动场景采用有线链路、预定的接入变化、单一移动生产者和受信任信令路径。
控制器服务通过事件调度表示决策到安装的时延。
处理时延敏感性实验为每个被接受且未命中缓存的 Interest 及每个收到的 Data 报文设置独立定时器。
不同报文的定时可以重叠。
所提供的 6744 微秒设置是该定时器的附加时延输入。
流表流水线、待处理状态、路由更新和计数器均作为软件在该事件模型中执行。

占用场景通过 Statim 状态更新路径插入互不相同的前缀，在可选的初始突发之后采用指数分布的到达间隔。
这些合成更新保持有效直至控制器完成；内部截止字段为零表示此无有限到期的租约。
每个接受的更新经过配置的确定性时延完成。
观测时长截止于最后一次到达时刻加上该时延。
时间加权占用包含启动和最终排空过程；零突发时的稳态参照值为到达率乘以平均驻留时间。
报告的占用统计活跃临时转发条目，持久代次记录属于单独的资源类别。

可选的软件计时通过 `std::chrono::steady_clock` 测量指定的宿主机操作。
查找样本执行临时 FIB 最长前缀匹配及带序列化的流表查找。
更新样本分别启停代次记录、临时前缀替换、控制消息构造及回调分发。
名字和哈希在计时前准备，批次均值用于摊薄计时调用的开销。
这些结果描述所选宿主机、编译器、容器和合成输入的执行成本。
